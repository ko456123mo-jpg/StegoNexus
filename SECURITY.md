# Security Policy

## Supported versions / الإصدارات المدعومة

| Version | Supported |
|---|---|
| 1.x | ✅ |

## Reporting a vulnerability / الإبلاغ عن ثغرة

**Please do not open a public issue for security problems.**

Email: **moh123mon456@gmail.com** with:

- A clear description and the potential impact
- Reproduction steps or a proof of concept
- The affected module (`stegonexus/core/*`, GUI, CLI, network channel)
- Version / commit hash

| Commitments | |
|---|---|
| Acknowledgement | within 72 hours |
| Initial assessment | within 7 days |
| Fix for critical issues | within 30 days |
| Credit | in `CHANGELOG` / release notes, if you wish |

## Scope

Testing is allowed **only against a local copy running on your own machine**.
Not allowed: hosted instances, other users' data, hosting infrastructure, or
any social-engineering attempt.

## By-design behaviour (not vulnerabilities)

| Behaviour | Why |
|---|---|
| Network transmission disabled by default | Safety: requires explicit *Authorized laboratory mode* + loopback/RFC1918 destinations only |
| Malware module is **static analysis only** | It never executes specimens or offers detonation — by design |
| Missing tools reported as `UNAVAILABLE` | The app refuses to fabricate results rather than guessing |
| Evidence treated as read-only | Operations run on working/derived copies; every action is audited |
| `demo_output/sample_payload.exe` is synthetic | Generated by `demo.py` from a seeded RNG; it is never executed |

## Secrets

- No `.env` or credentials are part of this repository.
- Network covert channels bind only to loopback / private ranges.
- Sample cases are labelled **TRAINING CASE — SYNTHETIC DATA**.
